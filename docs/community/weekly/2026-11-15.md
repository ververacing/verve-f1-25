## (b) Insights for Verve

1. **[harness]** Swofty now sets the safety car, formation lap, penalties and corner-cutting options by name: `safety_car_frequency`, `formation_lap`, `rules_and_penalties_mode`, `corner_cutting_mode`, via `Game_OptionsStore_FindOption` and vtable get/set (SwoftyLauncher `docs/std/content.md:434`, `native/src/core/box_options.cpp:16-23`, commit 3b757dbeed). This is the route source_insights A2 proposed, and it's now upstream with the option names. A content-package box with `rules.safety_car: "off"` and `rules.formation_lap: false` may give fixed test rules without a verve.harness DLL. It applies only when a box is pressed, so it needs checking on our Grand Prix path. AI difficulty isn't covered.
2. **[harness]** Standstill hand-over to the AI: Manual Pit Lane sets the PIT_LANE flag on the car's ControllerSet (+0x30) and writes mode 1 (XOR the key), then hands control back after 3 s or above 5 km/h (`kizi.pitlane native/src/pitlane.cpp:4-8, 559-597`, repo 0.3.6; the 0.3.9 throttle fix isn't public). That's a second way to give the player car to the AI on the grid (source_insights A1), without Race Broadcast's 20 m/s gate.
3. **[race-feel]** Two more authors confirm that raw overtake events are noise. Silly Season: the core reports an overtake "at every change of the classification", which made hundreds in a five-lap race (`alexs.silly-season native/src/plugin.cpp:1738-1740`). It counts one pass per pair per 30 s window and drops passes given back in that window (`:1753`, `:1862-1874`). Our held-pass window is 10 s. Report a 30 s variant next to `held_passes_net` as a sensitivity check.
4. **[race-feel]** Collision events repeat: "the game sends a message for every touch of a scrape: one incident is 3 s of them" (`alexs.pulse native/src/session.hpp:255-257`). Check that `race_feel.py` merges COLL events per pair within about 3 s before counting lap-1 and rear-end contacts.
5. **[harness]** In a native probe, the core's event car ids are "participant indices" and don't always match the live state's vehicle ids. PULSE remaps them by place via UDP (`session.hpp:664-692`). Silly Season found the core's `telemetry::session/car/participant` reads returned nothing in game, and reads Swofty's shared-memory feed directly (`plugin.cpp:1755-1756, 1764-1800`). Driver ids are only filled when the game's UDP output is on (`:1816-1818`). Our harness already uses UDP, so this matters only for a native probe.
6. **[personality]** Driver Momentum shows per-driver blocking distance as a live scale layer: `ai.blocking.max_blocking_distance` x 2^(form x k), with k = 1.0 on Normal, so 0.5x to 2x (`alexs.driver-momentum native/src/ai_writes.hpp:108-116`, `form_state.hpp:32-41`). It's the same lever as B-0015, from a second author. It doesn't touch the `_at_race_start` pair, so it does nothing during the race-start phase.
7. **[race-feel]** Driver Momentum keeps Driver Form's "moments": difficulty x0.35 for 3-8 s, at up to 0.5 per minute for an out-of-form car (`patches.hpp:39-46`, `ai_writes.hpp:87-88`). New: nothing in the first 60 s of a race (`patches.hpp:24-27`). Both are set off by the `bad_patches` option (`driver_form.cpp:271`).
8. **[career]** For career storage, `career::saves::current()` can return a shared `dc-<driver>` id when a career is loaded with Continue, so two careers of the same driver share data. F2 Revamp 0.9.1 resolves it to the save-slot id (`miguelvf3 f2-feeder-career/native/src/f2_feeder.cpp:450-458, 521-527`). Driver Momentum still uses `saves::current()` directly (`driver_form.cpp:207-215`), so its streaks may leak between careers. Verve's career data must resolve the slot id the same way.
9. **[career]** Driver Momentum keys drivers on `entrants.drivers` stat_id, verified against the DB row. It refuses a stat id that appears on two cars (`build_drivers.hpp:59-70, 198-209`). It also publishes a versioned `services` struct, `driver_momentum.form` (`native/include/driver_momentum_api/form.hpp:14-28`). Both are good patterns for Verve's own identity key and services interface (source_insights D).
10. **[CPU]** Two more examples of reading the DB once on a background thread: Driver Momentum's driver_statistics read (`ratings.hpp:120-160`), and Silly Season, which removed a 2 s Team HQ freeze this way (`plugin.cpp:1240-1265`).
11. **[compatibility]** From 1.9.56, an addon hook at an address the core already hooks is chained instead of silently dropped (commit 132d9b89ea). Addons that wrap game functions (Skip Cutscenes, Contact Physics) may behave differently after the update. After updating, re-check Skip Cutscenes' "removing" lines in loader.log.

## (c) Conflicts

- **AI Driver Behaviour 0.1.10 vs launcher 1.9.51-1.9.55:** Play fails with "string longer than 255 bytes" (1.9.56 notes). Tyler has AI Driver Behaviour, and the PC is on 1.9.51. If 0.1.10 shows up in the catalog before 1.9.56 is out and installed, don't take it.
- **Driver Momentum vs Verve:** it writes difficulty, four driver characteristics, base lap time (profile+0x148) and a blocking layer per driver (`ai_writes.hpp:75-116`). That's the same surface as Verve's personality and B-0015. It also conflicts with Driver Form (its author says so). It isn't in Tyler's profile.
- **AI Straight-line Nerf:** its live power cut also applies to the player car while the AI drives it (catalog text), and the author says it slows corner exits too. It would bias any harness arm that hands the player car to the AI, and probably race starts. It's closed source, so the field it changes can't be checked.
- **Aggressive AI Alt 3.0.0:** crashes on load, and a launcher that already installed it keeps it. Use 2.0.1 (the version our page documents) or 3.0.1 for the P2 screen.
- **Smarter AI Strategies 1.3.0:** no conflicts with Tyler's other add-ons stated or seen. Its changes only apply in rain.
- Silly Season and F2 Revamp aren't in Tyler's list. Silly Season still writes ratings only for new talents (`plugin.cpp:913-931`), so the source_insights D note stands.
