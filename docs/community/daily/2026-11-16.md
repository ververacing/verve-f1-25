## (b) Insights for Verve

1. **[harness]** Our pedal note is wrong. Swofty's KB fixed the InputRecord pedal names on 14 Nov: **+0x0c is the brake
   and +0x18 the throttle** (SwoftyLauncher `re/db/structs/InputRecord.h:9,12`, `re/db/subsystems/ai.md:221` item 7).
   `docs/community/source_insights.md:36` still says throttle +0x0c and brake +0x18. Our tools are unaffected:
   `race_feel.py` reads the brake from UDP.
2. **[race-feel]** AI Driver Behaviour 0.2.0's slide reaction starts when slip passes 7° above 15 m/s (checked at
   20 Hz). It then freezes steering and the "throttle" at +0x0c for 0.25 s ±30 % on the default "More" (0.15 s on Some,
   0.4 s on Lots) (`ai_driver_behaviour.cpp:15-18, 60-72, 113-121, 174-209`).
   - By insight 1, the pedal it holds is really the **brake**. An AI car that slides while braking keeps that brake on
     for about a quarter second.
   - It is signature-scanned (`:255-281`), so it should run on 26566308. It logs `[ai-driver-behaviour] slide
     reaction, last 30 s: …`.
3. **[harness]** `ai_drives_player` is still KB-only on `main` (details in watch item 1). But the core's own session op
   `sessions::set_control(car, ai)` is not gated on `same_build()`:
   - It checks only `runtime::enabled("events")` (`hooks/session_points.cpp:40-49`, `op_set_control` at
     `session_points.hpp:509-530`).
   - Its binding `Game_Set_VehicleController_Thunk` resolves on 26566308 (`re/db/builds/steam-26566308.json:82,5121`).
   - #1264's static pass found the controller-set layout unchanged: sets at +0x30, vehicle at +0x34, human controller
     at +0x20 (`re/research/live-steam-26566308.md`, "Controllers").

   So a small native verve add-on that calls `set_control(player, ai)` at `race.start` may hand the player car to the
   AI on 1.0.145. That's source_insights A1, and it's untested. Swofty's own page still calls the feature "implemented,
   waiting on verification" (`docs/std/systems/sessions.md:583`). Its fields are still the KB layout's, so it needs one
   proof race outside a batch. The F-46 garage route stays the only proven route.
4. **[compatibility]** Starting Grid 0.1.4 replaced every hard-coded RVA with a 26566308 value
   (`editor_rows.hpp:33-35`, `grand_prix_screen.hpp:17-21`, `grid_table.hpp:19-20,58`, `menu_option.hpp:16-17`).
   - It now **does nothing on 25251167**, and will break again on the next game patch.
   - It fails safe: it compares the vtable entry first and logs `[starting-grid] this game build is not supported: the
     grid can't be changed` (`grid_table.hpp:37-45`; also `grand_prix_screen.hpp:99`, `grid_editor.hpp:213`).
5. **[personality]** Driver Momentum 0.1.1 has a pattern for Verve's own native writes after a game update. It writes
   only when the AI manager's +0x38 is the same AiSystem that Swofty's site binding `site_Ai_BuildSystem_RecordPushed`
   caught (rbx) (`ai_driver.hpp:61-96`, `driver_form.cpp:510-520`). Then it range-checks every car's values before any
   write:
   - base lap time 30-250 s;
   - characteristics and difficulty 0-2;
   - one record per car;
   - the field's lap times within 0.8-1.25 x the median.

   If any check fails it leaves every car alone and logs why (`build_drivers.hpp:185-219`).
6. **[career]** On 1.0.145, the launcher binding `Career_Get_DriverOverallRating` doesn't resolve yet. Silly Season
   falls back to its own rating model and logs the missing binding by name (`game_ratings.inl:105-109`). It also logs
   the exe's PE timestamp and image size at load (`plugin.cpp:4882-4889`). Verve's career and ratings reads need the
   same fallback until the launcher catches up.
7. **[harness]** Track-limits penalties are plain database rules: `rules.multiple_warnings.penalty_frequency` and
   `…penalty_level[_metadata_=penalty].level`, plus the `accumulated_time` variant (Four Warning Limit `rules.json:4-21`).
   That's one more fixed-rules lever next to the `content.package` box rules. Swofty 1.9.61 also adds
   `session.points` / `rules.points` and `rules.mandatory_tyre_change` (`docs/releases/1.9.61.md:22-23`).
8. **[race-feel]** Contact Physics 0.8.0's aero loss lowers a car's downforce to 30 % above 15° of slip. It goes
   through Swofty's live car field `aero_lift_scale` (`ai_tweaks.cpp:772-786`). Spins slide further, so expect more
   yellows and safety cars with it on. It also moves the hit reaction into AI Driver Behaviour (`ai_tweaks.cpp:573-590`).
9. **[CPU]** Smarter AI Strategies 1.3.2 "finds its game code on future game updates by itself" (`CHANGELOG.md`). Yet
   its manifest still pins `game_builds ["=25251167"]`. A runtime scan doesn't help while the manifest gate keeps it
   off.
